## 5 Сравнение сборщиков (Webpack vs Esbuild + SWC)

В рамках оптимизации проекта была настроена альтернативная production-сборка. Процесс разделен на два этапа:

1. Компиляция TypeScript/JSX кода через **SWC** (транспилятор на Rust).
2. Сборка (бандлинг), минификация кода и ресурсов через **Esbuild**.

Конфигурационный скрипт расположен в корне проекта: `esbuild.config.js`.

Команды для сборок:
npm run build (webpack)
npm run build:esbuild (esbuild + SWC)

### Метрики производительности

| Скрипт сборки           | Время сборки (Build Time) | Размер бандла (Output Size) | Количество файлов | Применяемые технологии |
| :---------------------- | :------------------------ | :-------------------------- | :---------------- | :--------------------- |
| `npm run build`         | _10.5s_                   | **3.3 MB** (3 300 152 Б)    | 10 объектов       |
| `npm run build:esbuild` | _1s_                      | **4.6 MB** (4 586 424 Б)    | 16 объектов       |

> _Примечание: Замеры производились на локальной машине пользователя. Размер бандла указан как суммарный вес выходной директории сборщика._

### Выводы

1. **Скорость компиляции:** Использование связки Esbuild + SWC сократило время сборки в несколько раз. Это достигается за счет отсутствия накладных расходов виртуальной машины Node.js, так как оба инструмента написаны на низкоуровневых компилируемых языках с поддержкой многопоточности (Rust и Go).
2. **Размер и структура бандла:** Папка `dist-esbuild` получилась больше (4.6 МБ против 3.3 МБ у Webpack) и содержит больше объектов (16 против 10). Это обусловлено следующими факторами:
   - **Разделение ресурсов (Assets):** В отличие от Webpack, который по умолчанию может преобразовывать мелкие картинки и SVG в base64-строки и зашивать их прямо внутрь JS-кода (Inlining), конфигурация Esbuild вынесла статические медиа-файлы в отдельные объекты, что увеличило общее число элементов в папке.
   - **Алгоритмы минификации:** Webpack использует TerserPlugin, который выполняет более глубокий и агрессивный статический анализ (Dead Code Elimination), в то время как Esbuild делает ставку на максимальную скорость минификации, жертвуя парой сотен килобайт ради экономии времени.
3. **Изоляция окружения:** Скрипт успешно изолирован от глобальных конфигураций операционной системы и корректно разрешает абсолютные импорты (`shared`, `features` и др.), заложенные архитектурой проекта.
